Install notes
=============

Unpack the contents of this archive into "/assets/modules/error404logger" folder.

The module requires evolution-jp 1.3 or later (it uses the manager's DataTable).

Create a module in MODx and copy the contents of file "e404logger.module.php" into it.
Name the module "Error 404 Logger".
Copy the config string into "Module configuration" field and set the preferences.

Create a plugin in MODx and copy the contents of file "e404logger.plugin.php" into it.
Name the plugin "Error404Logger".
Check the "OnPageNotFound" system event.
(The "OnWebPageInit" event is no longer used since 0.3. You can uncheck it.)

And there you go!

All 404 error (page not found) are logged in a separate table and browsable through the module.




Changelog
=========
0.3
----
* evolution-jp 1.3: the module draws its tables with DataTable / DataTablePager (DataGrid was removed from the core)
* the module is shown inside the manager shell; the entries are paged with LIMIT instead of fetching all rows
* removing / clearing entries is done by POST (checked by the core CSRF token) instead of GET, without inline onclick
* removing an entry of "Most wanted" works for percent-encoded URLs (the URL is no longer decoded twice)
* "Clear all but last N days" uses the module setting keepLastDays (it was always 7)
* the plugin no longer redirects to ?e404_redirect= (open redirect); the module opens the referer directly with rel="noreferrer"
* only http(s) URLs and site paths are shown as links
* the reverse DNS lookup (gethostbyaddr) no longer slows down every 404:
  robots are matched against the User-Agent first (no lookup when it matches),
  the host is looked up once per request and reused from an earlier entry of the same IP (failed lookups too),
  and the new plugin setting &resolve_host=no turns the lookup off
* the robots check uses the logged client IP (remoteIPIndexName) instead of REMOTE_ADDR, and ignores case
